# 经历映射（最重要）

> 可信度标注：★1-5  
> 本文件核心目标：将学生/转行者常见经历，转化为运营岗认可的简历语言

---

## 使用指南

每条经历映射包含以下维度：

- **经历名称**：常见叫法
- **可证明的岗位能力**：这条经历能支撑哪些运营能力
- **简历价值等级**：高/中/低（基于与运营岗的相关性）
- **推荐表达方向**：STAR法则下的表达侧重
- **追问点**：面试官可能深挖的问题
- **无数据时的处理**：没有明确数字时的补救策略
- **禁止编造的内容**：红线

---

## 1. 学生会/社团运营

| 维度        | 内容                                                                         |
| --------- | -------------------------------------------------------------------------- |
| **可证明能力** | 活动策划、跨部门协调、资源调配、用户（成员）管理、项目管理、文案撰写                                         |
| **价值等级**  | 中-高（取决于规模和成果）                                                              |
| **推荐表达**  | 聚焦"你负责什么→服务了多少人→达成了什么目标"。例："负责社团招新运营，策划3场线上宣讲+1场线下活动，覆盖500+新生，招新人数同比增长40%" |
| **追问点**   | 活动预算多少？如何分工？遇到的最大困难？如何评估效果？                                                |
| **无数据处理** | 用覆盖人数、活动场次、参与率、满意度等替代；或对比前后变化（"从松散管理到建立SOP"）                               |
| **禁止编造**  | 不要虚构社团级别（如"校级"vs"院级"）；不要夸大管理人数                                             |

## 2. 公众号/小红书/抖音运营

| 维度        | 内容                                                                                        |
| --------- | ----------------------------------------------------------------------------------------- |
| **可证明能力** | 内容策划、选题能力、平台规则理解、数据分析、用户增长、文案撰写、视觉审美                                                      |
| **价值等级**  | **高**（最直接相关，尤其是有真实数据时）                                                                    |
| **推荐表达**  | 必须带数据：粉丝量、阅读量/播放量、互动率、涨粉速度、爆款数量。例："独立运营个人成长类公众号，3个月积累3000精准粉丝，产出2篇1万+阅读，平均打开率12%（行业均值5%）" |
| **追问点**   | 选题怎么来的？最爆款的内容是怎么做的？粉丝画像是什么？变现尝试过吗？                                                        |
| **无数据处理** | 即使数据小，也可以强调增速（"从0到500粉丝"）、或内容质量（"持续日更30天"）、或技能掌握（"独立完成选题-撰写-排版-发布全流程"）                    |
| **禁止编造**  | **严禁PS后台数据**；不要买粉/刷量后写入简历；不要搬运他人内容说是原创                                                    |

| **推荐表达**  | 强调平台认知和实际成果。例："在Shopee运营家居小件店铺，独立完成Listing撰写和关键词优化，月出单50+，通过分析评价数据优化产品描述，退货率从15%降至8%" |
| **追问点**   | 怎么解决语言问题？物流怎么处理的？遇到过什么合规问题？                                                           |
| **无数据处理** | 用平台数、上架SKU数、服务国家数、处理订单数、优化次数替代                                                        |
| **禁止编造**  | 不要虚构跨境经历；不要把代购说成"跨境电商运营"                                                              |

## 19. 设计/视频制作（非专业）

| 维度        | 内容                                                                                   |
| --------- | ------------------------------------------------------------------------------------ |
| **可证明能力** | 视觉表达、工具应用、审美能力、多媒体内容生产                                                               |
| **价值等级**  | 中（内容/新媒体运营岗加分）                                                                       |
| **推荐表达**  | 聚焦产出和应用场景。例："自学PS/剪映，为社团活动制作海报15张、短视频8条，其中2条播放量超5000，掌握基础调色和字幕动效制作，能独立完成从脚本到成片的辅助工作" |
| **追问点**   | 作品发在哪里？接过商业需求吗？设计灵感从哪来？                                                              |
| **无数据处理** | 用作品数量、使用工具数、服务场景数、学习时长替代                                                             |
| **禁止编造**  | 不要把模板套用说成"原创设计"；不要拿别人的作品充数                                                           |

## 通用表达公式（STAR+数据）

```
情境(S)：在什么背景下
    ↓
任务(T)：接到了什么目标/指标
    ↓
行动(A)：你具体做了什么（我主导/我设计/我分析）
    ↓
结果(R)：达成了什么（必须有数字）
    ↓
复盘(L)：学到了什么/如果重来会怎么做（面试备用）
```

## 无数据时的万能补救策略

| 策略          | 适用场景    | 示例                      |
| ----------- | ------- | ----------------------- |
| **强调增速/倍数** | 基数小但增长快 | "从0到500粉丝""效率提升1倍"      |
| **强调方法论**   | 过程有价值   | "建立XX流程/SOP""设计XX机制"    |
| **强调规模/覆盖** | 接触过大量用户 | "服务XX人""覆盖XX个班级/楼栋"     |
| **强调投入/坚持** | 体现执行力   | "持续更新XX天""投入XX小时"       |
| **强调反馈/评价** | 有外部认可   | "获指导老师优秀评价""用户满意度4.5/5" |
| **对比法**     | 有前后变化   | "优化前XX，优化后XX"           |

## 绝对禁止编造的内容（红线）

| 类型          | 说明                       | 后果            |
| ----------- | ------------------------ | ------------- |
| **虚构数据**    | 后台截图可验证的数字（粉丝量、阅读量、GMV等） | 面试一问即穿，诚信一票否决 |
| **虚构职务**    | 把参与者写成负责人、把部员写成部长        | 背调可核实         |
| **虚构公司/项目** | 编造不存在的实习或创业经历            | 严重诚信问题        |
| **抄袭作品**    | 把他人内容/设计说成原创             | 作品集环节直接暴露     |
| **夸大贡献**    | 把团队成果全揽在自己身上             | 追问细节即露馅       |
| **PS数据截图**  | 修改后台数据截图                 | 技术验证简单，风险极高   |
| **虚构技能熟练度** | 写"精通SQL"但现场写不出基础查询       | 技能面试直接淘汰      |
