# 产品经理 — 经历映射

> 本文件是简历优化的核心参考。对每种常见经历，提供能力映射、价值判断、表达方向、追问预警。
>
> 可信度标注：★1-5

---

## 使用说明

- **经历名称**：常见的校园/职场经历
- **可证明的岗位能力**：该经历能体现的产品经理核心素质
- **简历价值等级**：高/中/低，决定该经历在简历中的位置和篇幅
- **推荐表达方向**：如何用产品思维重新包装这段经历
- **追问点**：面试官可能深挖的方向，需提前准备
- **无数据时的处理**：缺乏量化指标时的替代策略
- **禁止编造的内容**：涉及背调/验证的红线

## 1. 产品分析/体验报告

| 维度 | 内容 |
|---|---|
| **可证明的岗位能力** | 产品思维、用户洞察、竞品分析、结构化表达 |
| **简历价值等级** | **高**（对无经验者是核心作品） |
| **推荐表达方向** | 不写"我写了一篇报告"，写"通过X方法发现Y问题，提出Z优化方案，若上线预计可带来..." |
| **追问点** | 为什么选这个产品？你的目标用户画像怎么得出的？你的方案技术上可实现吗？数据怎么验证？ |
| **无数据时的处理** | 用"若按此方案执行，基于行业平均转化率估算..."做合理推演；或找公开数据支撑 |
| **禁止编造的内容** | 不要谎称报告被某公司采纳/引用；不要编造与产品经理的访谈内容 |

### 表达模板
> 深度体验[产品名]，针对[具体场景/功能]展开分析。通过[调研方法]识别出[用户痛点]，对比[竞品]后发现[差异化机会]，提出[具体优化方案]，预计可改善[某指标]。

## 2. 课程项目（含产品设计）

| 维度 | 内容 |
|---|---|
| **可证明的岗位能力** | 需求分析、产品设计、原型制作、团队协作、汇报表达 |
| **简历价值等级** | **高**（尤其是有完整PRD/原型的项目） |
| **推荐表达方向** | 按真实产品项目写：背景→目标用户→需求分析→功能设计→原型/PRD→成果 |
| **追问点** | 用户需求怎么调研的？为什么选这个功能而非其他？项目中的分工和冲突？ |
| **无数据时的处理** | 强调方法论和过程完整性；若有课程评分/展示可写"获得课程最高分/优秀项目" |
| **禁止编造的内容** | 不要虚构用户访谈数量和对象；不要夸大项目实际落地情况 |

## 3. 创业/小项目

| 维度 | 内容 |
|---|---|
| **可证明的岗位能力** | 全链路产品思维、资源整合、执行力、抗压能力、商业化意识 |
| **简历价值等级** | **高**（真实上线且有用户的项目价值极高） |

| **无数据时的处理** | 用"冷启动获取X名种子用户""用户反馈中Y%提到某痛点"等替代 |
| **禁止编造的内容** | 用户数、收入、融资情况（最易背调）；不要隐瞒项目是课程作业的性质 |

## 4. App/小程序/网站开发

| 维度 | 内容 |
|---|---|

## 7. 社团/班级需求解决

|---|---|
| **可证明的岗位能力** | 需求发现、问题解决、资源协调、小范围产品化思维 |
| **简历价值等级** | **中**（包装得当可显著加分） |

## 15. 其他可映射经历

- **可证明能力**：一线用户理解、痛点感知、沟通技巧
- **价值等级**：中
- **表达方向**："直接面对用户，积累了XX类用户的核心诉求和决策因素"

### 翻译/外语相关
- **可证明能力**：出海产品语言/文化适配、信息整合
- **价值等级**：中
- **表达方向**：结合出海产品趋势，强调跨文化理解

- **可证明能力**：内容产品思维、用户增长、数据分析（后台数据）、商业化
- **价值等级**：中-高（视粉丝量和数据表现）

### 家教/培训
- **可证明能力**：需求诊断、方案定制、效果评估
- **价值等级**：低

## 通用原则 ★★★★★

1. **STAR法则是底线**：每段经历必须有背景、任务、行动、结果
2. **数据优先**：能用数字不用形容词，"大幅提升"→"提升37%"
3. **产品语言翻译**：把任何经历翻译成"问题→分析→方案→验证"的结构
4. **少即是多**：2-3个深度经历 > 5个浅度经历
5. **诚实边界**：可以包装表达方式，不可以编造事实
