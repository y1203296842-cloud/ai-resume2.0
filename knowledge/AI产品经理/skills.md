# AI产品经理 — 技能需求分析

> 可信度标注：★1-5

---

## 核心技能（S级）

### 1. 大模型认知与选型能力
- **重要性：** S
- **为什么重要：** 这是AI PM的"专业壁垒"。同一任务用GPT-4、Claude、国产模型或微调模型，效果、成本、合规性差异巨大。选错模型直接导致产品失败。★★★★★
- **如何证明：**
  - 简历写明"基于XX业务需求，对比测试3+模型，最终选型XX，推理成本降低X%"
  - 面试能清晰对比主流模型在特定任务上的优劣
  - 有模型选型决策文档或评测记录

### 2. Prompt Engineering
- **重要性：** S
- **为什么重要：** Prompt是AI PM的"PRD"。不会写结构化Prompt的AI PM，如同不会写需求文档的传统PM。优秀的Prompt直接决定产品体验上限。★★★★★
- **如何证明：**
  - 展示系统化的Prompt模板库（含角色设定、 few-shot示例、输出格式约束）
  - 量化指标："通过Prompt优化，输出准确率从65%提升至92%"
  - GitHub或个人知识库中的Prompt工程实践记录

### 3. AI场景落地能力
- **重要性：** S
- **为什么重要：** 行业不缺懂AI的人，缺的是能识别"什么业务痛点值得用AI解决"的人。80%的AI项目死于伪需求。★★★★★
- **如何证明：**
  - 完整案例：从业务痛点 → 技术方案 → 上线验证 → ROI数据
  - 能清晰回答"为什么这个场景不用规则引擎/传统算法，而必须用LLM"
  - 有失败案例复盘（更有说服力）

### 4. AI工作流设计
- **重要性：** S
- **为什么重要：** 单点AI调用往往不够，需要将RAG、Agent、多模型路由、人工审核等环节编排为完整链路。这是产品架构能力的AI延伸。★★★★★
- **如何证明：**
  - 画出并讲解某个AI功能的完整技术链路图
  - 说明每个节点的设计决策（为什么加RAG？什么时候触发人工审核？）

### 5. 用户需求分析（传统能力迁移）
- **重要性：** S
- **为什么重要：** AI PM首先是PM。如果用户调研、需求优先级判断、交互设计基本功不扎实，技术再强也做不出好产品。★★★★★
- **如何证明：** 同传统PM，但需补充"AI场景下的用户接受度调研"经验

### 6. 产品原型与验证
- **重要性：** S
- **为什么重要：** AI产品的不确定性更高，更需要低成本快速验证。会用AI原生原型工具或搭建可交互Demo是加分项。★★★★☆
- **如何证明：** 展示AI功能的低保真/高保真原型，及对应的用户测试数据

## 重要技能（A级）

### 7. RAG（检索增强生成）
- **重要性：** A
- **为什么重要：** 企业级AI应用的核心架构之一。不懂RAG的边界和设计要点，无法做知识库类、问答类产品。★★★★★
- **如何证明：** 说明参与过的RAG项目中的职责（Chunk策略设计、召回率优化、重排序逻辑等）

### 8. Agent设计与编排
- **重要性：** A
- **为什么重要：** 2024-2025年最热方向。Agent产品需要PM设计任务拆解逻辑、工具调用策略、记忆机制。★★★★★
- **如何证明：** 展示Agent工作流设计，说明State Machine或ReAct模式的落地经验

### 9. Function Calling / 工具调用
- **重要性：** A
- **为什么重要：** 让LLM从"聊天"升级为"行动"的关键能力，是Agent产品的技术底座。★★★★☆
- **如何证明：** 有调用外部API/插件的设计经验，能说明参数定义和错误处理策略

### 10. 模型能力边界理解
- **重要性：** A
- **为什么重要：** 知道模型"什么做不到"比"什么能做到"更重要。这是设计兜底策略和用户体验的前提。★★★★★
- **如何证明：** 能列举具体业务场景中模型的失效模式，及对应的产品化解决方案

### 11. Evaluation（评测体系）
- **重要性：** A
- **为什么重要：** AI产品没有标准答案，必须自建评测标准。不会评估模型效果的PM无法做迭代决策。★★★★★
- **如何证明：** 设计过评测指标（准确率、相关性、安全性等）和评测数据集

### 12. Token管理与成本控制
- **重要性：** A
- **为什么重要：** AI产品的单位经济模型与传统软件完全不同。Token消耗直接决定产品能否商业化。★★★★☆
- **如何证明：** 有优化Token消耗的具体数据（如"通过Prompt压缩和缓存策略，单次调用成本降低40%"）

## 加分技能（B级）

| 技能 | 价值说明 | 可信度 |
|---|---|:---:|
| 微调（Fine-tuning）经验 | 理解数据准备、训练流程、过拟合风险，能与算法团队同频沟通 | ★★★★☆ |
| 对齐（Alignment）与安全 | 了解RLHF、红队测试、内容安全策略，适合大模型平台方向 | ★★★★☆ |
| 向量数据库选型 | 熟悉Milvus、Pinecone、Qdrant等差异，RAG方向必备 | ★★★☆☆ |
| 数据标注与质量管理 | 能设计标注规范、评估标注一致性，直接影响模型效果 | ★★★★☆ |
| 代码能力（Python/SQL） | 能写简单脚本做数据分析或调用API测试，非必须但大幅提升效率 | ★★★☆☆ |
| 产品数据分析 | 能独立分析AI功能的使用漏斗、留存、满意度 | ★★★★★ |
| AI合规与伦理 | 了解算法备案、数据安全法、AIGC标识要求，B端必备 | ★★★★☆ |
| 多模态理解 | 涉及图文音视频的产品需要，当前岗位需求在增长 | ★★★☆☆ |

## 过时/弱相关技能

| 技能 | 原因 | 可信度 |
|---|---|:---:|
| "熟练使用ChatGPT" | 基础工具使用不构成竞争力，如同写"熟练使用Word" | ★★★★★ |
| 单纯的大模型概念科普 | 2023年的知识储备已不够，需要落地经验 | ★★★★★ |
| 传统前端/后端开发 | 不是必须，理解即可，除非做开发工具类产品 | ★★★☆☆ |
| 深度学习模型训练 | 算法工程师职责，PM只需理解原理和边界 | ★★★★☆ |
| 论文阅读与复现 | 研究型岗位需求，工程落地岗更看重效果而非理论 | ★★★☆☆ |
| 仅停留在AI绘画/生图 | Midjourney等工具使用≠AI PM能力，除非做AIGC产品 | ★★★★☆ |

## 与传统产品经理技能差异对比表

| 技能领域 | 传统PM要求 | AI PM额外/差异化要求 | 关键变化 |
|---|---|---|---|
| **需求文档** | PRD、流程图、用例 | + Prompt Design Doc、模型选型说明、效果预期指标 | 文档体系扩展 |
| **技术沟通** | 理解前后端分工 | + 理解模型能力边界、Token机制、推理链路 | 对话对象增加算法团队 |
| **效果评估** | 功能是否可用、用户满意度 | + 模型准确率、幻觉率、延迟、成本/Token | 量化维度增加 |
| **原型工具** | Figma/Axure | + AI原型工具、可直接调模型的Demo | 原型需体现AI交互 |
| **迭代驱动** | 用户反馈+业务需求 | + 模型迭代+数据飞轮+效果评测 | 双轮驱动 |
| **风险意识** | 业务合规、数据安全 | + 幻觉、偏见、提示注入、模型失控 | AI特有风险 |
| **交付标准** | 功能上线即里程碑 | 上线只是开始，效果达标才是里程碑 | 里程碑后移 |
| **成本意识** | 人力成本、时间成本 | + Token成本、推理成本、标注成本 | 单位经济模型变化 |

## 技能证明优先级建议

**简历中优先展示的顺序：**
1. 完整AI产品落地案例（场景+方案+数据）
2. Prompt工程效果量化
3. 模型选型与技术成本评估经验
4. 跨团队协作（尤其是与算法团队）
5. 传统产品基本功（作为底座）

**面试中优先准备的深度话题：**
1. 一个你主导的最复杂的AI功能，完整决策链条
2. 模型在某场景下的失效案例及你的应对
3. 如果预算减半，你会如何调整AI方案
